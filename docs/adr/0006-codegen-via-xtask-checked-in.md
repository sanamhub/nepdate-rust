# ADR-0006: Generate Rust tables from `shared/data/` with `cargo xtask`, commit the output

- **Status:** accepted (amended by ADR-0022)
- **Date:** 2026-09-24 (revised 2026-10-07: patro tables move to `nepdate-patro`; revised 2026-10-08:
  table layout from ADR-0004)
- **Approved by:** Sanam

## Context

`shared/data/*.json` must become Rust `const`/`static` arrays. Options:

1. `build.rs` that parses JSON on every build.
2. A dev-time generator whose output is committed.
3. `include_str!` + runtime parsing.

(1) needs JSON parsing deps at build time for every downstream user and the crate
could not be published without shipping `shared/data/` inside it. (3) costs startup time and
needs `alloc`.

## Decision

- Use the **xtask pattern** (a workspace binary crate `xtask`, run with `cargo xtask <cmd>`
  via an alias in `.cargo/config.toml`).
- `cargo xtask codegen` reads `shared/data/` (using `serde_json`, a dependency of `xtask` only)
  and writes:
  - `crates/nepdate/src/generated/calendar.rs`: `PACKED_YEARS` and the range constants only.
    The derived tables (`MONTH_INFO`, `BS_MONTH_AD`, `AD_MONTH_START`, ADR-0004 §3) are **not**
    generated: `const fn`s in `crates/nepdate/src/calendar.rs` build them from `PACKED_YEARS` at
    compile time, so the generated file stays one line per year and can't drift from them.
  - `crates/nepdate-patro/src/generated/patro.rs`: the per-day tables, name tables and
    constants of ADR-0004 §6, from `shared/data/patro/*.json`. Here codegen does the work because
    the input is JSON.
- Codegen validates while it generates and fails with the BS date in the message: 299 years of
  12 lengths in 29..=32; epoch; tithi with no gap inside its range; every patro day inside the
  calendar range; `PATRO_DAYS` ≤ 65,535 and `EVENT_IDS.len()` ≤ 65,535 (they are `u16` offsets);
  at most 254 tithi names (`u8::MAX` means none).
- Every generated array gets a short comment per row (the BS year, or the BS date of the
  entry) so a reader can find a day in the diff.
- Generated files start with `// @generated by cargo xtask codegen. DO NOT EDIT.`
  and are committed.
- `cargo xtask codegen --check` regenerates in memory and fails if the committed files
  differ. CI runs it on every PR (drift check).
- Output must be deterministic (sorted, fixed formatting) and pass `rustfmt --check`.

## Consequences

- Library users compile zero codegen; `nepdate` and `nepdate-patro` publish cleanly to
  crates.io.
- Readers can check generated tables in diffs when data changes.
- One more crate in the workspace (`xtask`, `publish = false`).
