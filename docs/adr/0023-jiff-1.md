# ADR-0023: The `jiff` feature moves to jiff 1.x

- **Status:** accepted
- **Date:** 2026-11-17
- **Approved by:** Sanam
- **Amends:** ADR-0011 (the `jiff` feature depends on jiff 1.x, not 0.2.x)

## Context

ADR-0011 chose jiff 0.2.x for the `jiff` feature: the conversions to and from
`jiff::civil::Date`, `today()`, `today_in`, the relative predicates and the range `current_*`
factories. jiff 1.0 is out and promises to stay on 1.x. Its MSRV is Rust 1.85, the same as this
workspace. The breaking changes in jiff 1.0 do not touch the types this crate uses
(`civil::Date`, `Timestamp`, `tz::TimeZone`, `tz::Offset`). The main rename, `Zoned` to
`ZonedDateTime` and `Timestamp::to_zoned` to `Timestamp::to_zoned_datetime`, only reached the
tests.

jiff 0.2 and jiff 1 are different crates to Cargo. A caller whose own `jiff` is on another major
gets types that do not match the trait impls of this crate.

## Decision

1. The `jiff` feature of `nepdate` depends on `jiff = "1"`, with the same features as before
   (`std`, `tzdb-bundle-platform`, `tzdb-zoneinfo`, `tzdb-concatenated`).
2. The public items behind the feature keep their names and signatures, now with jiff 1 types.
3. The `nepdate-patro` dev-dependency on jiff moves to `"1"` with it, so the workspace builds one
   jiff.
4. The change is listed as breaking for the `jiff` feature in the `nepdate` changelog.
5. The rest of ADR-0011 stands.

## Consequences

- Users of the `jiff` feature move their own jiff to 1.x in the same step.
- The MSRV stays Rust 1.85.
- Callers who need jiff 0.2 stay on a `nepdate` release from before this change.
