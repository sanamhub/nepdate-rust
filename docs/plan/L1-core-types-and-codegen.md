# L1: Core types and calendar codegen

**Goal:** `NepaliDate::new` validates against the real calendar table, which is generated
from `shared/data/calendar/bs-calendar.json`. Plus `Month`, `Weekday`, `Lang`, `Error`.

Read first: ADR-0004, ADR-0006, ADR-0007, `shared/spec/ALGORITHM.md` §1–5, `docs/API.md`
(sections NepaliDate, names, errors), `shared/spec/FORMATTING.md` §1 (names table).
Human reads: `docs/learn/02-structs-enums-errors.md`.

## Tasks

### L1-01 `cargo xtask codegen` for the calendar

Reads `shared/data/calendar/bs-calendar.json` and writes
`crates/nepdate/src/generated/calendar.rs`:

```rust
// @generated by `cargo xtask codegen` from shared/data/calendar/bs-calendar.json. DO NOT EDIT.
// Source: https://github.com/RajuPrasai/NepDate @ <commit> (MIT). See shared/data/NOTICE.

/// First supported BS year.
pub(crate) const MIN_YEAR: u16 = 1901;
/// Last supported BS year.
pub(crate) const MAX_YEAR: u16 = 2199;
/// Number of supported years.
pub(crate) const YEARS: usize = 299;
/// Days since 1970-01-01 of 1901-01-01 BS (= 1844-04-11 AD).
pub(crate) const EPOCH_UNIX_DAYS: i32 = -45_920;

/// Month lengths, 2 bits per month: `length - 29`. Month 1 in bits 0..2.
// `const`, not `static`: const fns (build_month_info, NepaliDate::new) must read it at
// compile time, which is only guaranteed for consts on our MSRV.
pub(crate) const PACKED_YEARS: [u32; YEARS] = [
    0x0051_1ABA, // 1901: 31 31 32 31 31 31 30 29 30 29 30 30
    // ... one line per year, comment shows the 12 lengths
];
```

Rules:
- Validate while generating: 299 years, 12 values each, every value in 29..=32, epoch
  matches `EPOCH_UNIX_DAYS` (compute with the same `days_from_civil` as ALGORITHM §5).
  Fail loudly with the year number.
- Output is deterministic and rustfmt-clean. Hex with `_` digit grouping every 4 digits.
- `--check`: generate into memory, compare with the file on disk, exit 1 with
  "generated code is stale: run `cargo xtask codegen`" if different.

AC:
- Running codegen twice produces a byte-identical file.
- Editing one length in the JSON makes `cargo xtask codegen --check` fail.

### L1-02 Derived tables, built at compile time (`src/calendar.rs`, `src/civil.rs`, `pub(crate)`)

ADR-0004 §3 is the design; this task writes it. Only `PACKED_YEARS` is generated. The three
runtime tables are `static`s whose initializers are `const fn` calls, so the compiler computes
them and stores them in read-only data. Nothing runs at start-up.

`src/civil.rs`: ALGORITHM §5 copied line by line as `const fn`s in `i64`, keeping the spec's
variable names (`era`, `yoe`, `doy`, `doe`, `mp`). Use floor division for negative values
(`if y >= 0 { y } else { y - 399 } / 400`), so the functions are right for any year, not only
our range.

```rust
pub(crate) const fn days_from_civil(y: i64, m: i64, d: i64) -> i64 { /* ALGORITHM §5 */ }
pub(crate) const fn civil_from_days(z: i64) -> (i64, i64, i64) { /* ALGORITHM §5 */ }
pub(crate) const fn is_leap(y: i64) -> bool { (y % 4 == 0 && y % 100 != 0) || y % 400 == 0 }
pub(crate) const fn greg_month_length(y: i64, m: u8) -> u8 { /* 28..=31 */ }
```

`src/calendar.rs`:

```rust
mod generated { pub(crate) mod calendar; }    // in lib.rs

pub(crate) const MONTHS: usize = YEARS * 12;    // 3588
pub(crate) const AD_MONTHS: usize = 3589;       // 1844-04 ..= 2143-04
pub(crate) const MAX_SERIAL: u32 = 109_211;

/// Days in BS month, from PACKED_YEARS. const so NepaliDate::new (a const fn) can use it.
pub(crate) const fn month_length(year: u16, month: u8) -> u8 {
    let packed = PACKED_YEARS[(year - MIN_YEAR) as usize];
    29 + ((packed >> ((month - 1) * 2)) & 0b11) as u8
}

/// MONTH_INFO[i] = start serial of BS month i (i = (y - 1901) * 12 + m - 1) << 2 | (length - 29).
/// MONTH_INFO[MONTHS] = 109_212 << 2, so MONTH_INFO[i + 1] >> 2 is always the next start.
pub(crate) static MONTH_INFO: [u32; MONTHS + 1] = build_month_info();
/// AD date of the first day of BS month i, packed year << 9 | month << 5 | day.
pub(crate) static BS_MONTH_AD: [u32; MONTHS] = build_bs_month_ad();
/// Serial of the first day of AD month j (j = (y - 1844) * 12 + m - 4). Entry 0 is -10.
pub(crate) static AD_MONTH_START: [i32; AD_MONTHS] = build_ad_month_start();

const fn build_month_info() -> [u32; MONTHS + 1] {
    let mut out = [0u32; MONTHS + 1];
    let mut start = 0u32;
    let mut i = 0;
    while i < MONTHS {            // `for` loops are not allowed in const fn; `while` is
        let extra = (PACKED_YEARS[i / 12] >> ((i % 12) * 2)) & 0b11;
        out[i] = (start << 2) | extra;
        start += 29 + extra;
        i += 1;
    }
    out[MONTHS] = start << 2;
    out
}
// build_bs_month_ad: for each i, civil_from_days(start_serial + EPOCH_UNIX_DAYS), packed.
//   It calls build_month_info() again (compile time only) instead of reading the static:
//   the builders read only `const` items, never a `static` (ADR-0004 §3).
// build_ad_month_start: for each j, days_from_civil(y, m, 1) - EPOCH_UNIX_DAYS.

const _: () = assert!(build_month_info()[MONTHS] >> 2 == 109_212);
const _: () = assert!(days_from_civil(1844, 4, 11) == EPOCH_UNIX_DAYS as i64);
```

Indexing inside `const fn` with proven-in-range indices is allowed. Add
`#[allow(clippy::indexing_slicing)]` on these functions with a `// SAFETY-OF-INDEX:` comment
explaining why the index is in range. (It's not `unsafe`, just a clippy lint.) At run time, read
the statics with `.get(i)` where the index comes from input, or with a commented `allow` where a
range check just above proves it.

AC (unit tests in the same files):
- `MONTH_INFO[MONTHS] >> 2 == 109_212`; `MONTH_INFO[0] == 0b10` (1901 Baishakh, 31 days, start 0).
- `month_length(1901, 3) == 32`, `month_length(2081, 12) == 31`; for every month, the length from
  `MONTH_INFO` equals `month_length`.
- Year lengths: start of 2088 minus start of 2087 (`MONTH_INFO[187 * 12] >> 2` minus
  `MONTH_INFO[186 * 12] >> 2`) is 367; the same for 2090 is 364.
- `BS_MONTH_AD[0]` unpacks to 1844-04-11; `BS_MONTH_AD[(2081 - 1901) * 12]` to 2024-04-13.
- `AD_MONTH_START[0] == -10` (1844-04-01) and `AD_MONTH_START[3588] == 109_197` (2143-04-01).
- `PACKED_YEARS[0] == 0x0051_1ABA` (BS 1901).
- `days_from_civil(1970, 1, 1) == 0`, `days_from_civil(2000, 3, 1) == 11_017`,
  `civil_from_days(-1) == (1969, 12, 31)`, `days_from_civil(-1, 1, 1) == -719_893`
  (negative years work).
- The release build of a binary using these tables grows by 43 to 46 KB (ADR-0004: 43,008 B
  measured). Record the number in the PR.

### L1-03 `Error` and `ParseErrorKind` (`src/error.rs`)

Exactly as `docs/API.md`. `Display` messages (tests assert them):

| Variant | Message |
|---|---|
| `OutOfRange` | `date out of supported range (BS 1901-01-01 to 2199-12-30)` |
| `InvalidMonth(m)` | `invalid month {m}: expected 1 to 12` |
| `InvalidDay { month_length, day }` | `invalid day {day}: month has {month_length} days` |
| `InvalidGregorian` | `invalid Gregorian date` |
| `Parse(k)` | `could not parse date: {k}`, where k is `invalid character`, `expected year, month and day`, `number too long`, `ambiguous date`, `unrecognized date format` |

`impl std::error::Error for Error {}` behind `#[cfg(feature = "std")]`.

### L1-05 `NepaliDate` struct + `new` + getters (`src/date.rs`)

```rust
pub const fn new(year: u16, month: u8, day: u8) -> Result<Self, Error> {
    if year < MIN_YEAR || year > MAX_YEAR { return Err(Error::OutOfRange); }
    if month < 1 || month > 12 { return Err(Error::InvalidMonth(month)); }
    let len = month_length(year, month);
    if day < 1 || day > len { return Err(Error::InvalidDay { month_length: len, day }); }
    match Month::from_number(month) { Some(month) => Ok(Self { year, month, day }), None => Err(Error::InvalidMonth(month)) }
}
```

The struct is `NepaliDate { year: u16, month: Month, day: u8 }` (ADR-0004 §2), so `new` turns
the checked `u8` into `Month` with a `const fn Month::from_number(m: u8) -> Option<Month>` (a
`match` over 1..=12).
Also `MIN`, `MAX` (as `const` using an internal `new_unchecked` `const fn` that is
`pub(crate)`), `year()`, `month()`,
`month_number()`, `day()`, `month_length()`, `first_day_of_month()`,
`last_day_of_month()`, `Debug` = `NepaliDate(2081-04-15)`, `Display` = `2081/04/15`
(write with `write!(f, "{:04}/{:02}/{:02}", ...)`).

AC:
- Tests for each error branch, with the error precedence from ALGORITHM §3:
  `new(1900, 13, 40)` → `OutOfRange`; `new(2080, 13, 40)` → `InvalidMonth(13)`;
  `new(2080, 1, 32)` → `InvalidDay{31,32}`; `new(2081, 4, 32)` → Ok;
  `new(2081, 4, 33)` → `InvalidDay{32,33}`; `new(2081, 0, 1)` → `InvalidMonth(0)`;
  `new(2200, 1, 1)` → `OutOfRange`.
- `size_of::<NepaliDate>() == 4`, `size_of::<Option<NepaliDate>>() == 4` and
  `size_of::<Result<NepaliDate, Error>>() <= 4` (tests; ADR-0004 §2).
- Ordering test: `new(2080,12,30) < new(2081,1,1)`.
- Doctest on `new`.
